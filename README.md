# nightclub_roblox
Generated by [Rojo](https://github.com/rojo-rbx/rojo) 7.7.1.

## Getting Started
To build the place from scratch, use:

```bash
rojo build -o "nightclub_roblox.rbxlx"
```

Next, open `nightclub_roblox.rbxlx` in Roblox Studio and start the Rojo server:

```bash
rojo serve
```

For more help, check out [the Rojo documentation](https://rojo.space/docs).

## Phase 2: sprites and HUD

`src/client/SpriteAnimator.luau` renders 36 client-side guests using a single
RenderStepped loop. Empty `GameConfig.GUEST_SPRITE.AssetId` uses articulated UI
cartoons with walking limbs, dancing arms, faces, shadows, and VIP badges.
To use an original uploaded sheet, set that AssetId in `src/shared/GameConfig.luau`.
Use a 1024x1024 transparent atlas with sixteen 256x256 cells, ordered left to right:

- Row 1: Idle (frames 0?3, 4 FPS).
- Row 2: Walk (frames 4?7, 10 FPS).
- Rows 3?4: Dance (frames 8?15, 12 FPS).

Keep each character's feet at the bottom center of each cell. Clip definitions
support FPS, zero-based FirstFrame, FrameCount, and Looped; non-looping clips
hold their final frame. `Play(name)` preserves time when the clip is unchanged;
`Update(dt, zIndex)` advances frames; `Destroy()` releases the view. No individual
animator creates an event connection. All guest parts use the same tile depth.

TopHud stat capsules and BottomDock use procedural glossy gradients; toolbars
scale to window width. The DJ countdown refreshes once per second. Positive
server cash balance deltas generate a floating `+$Cash` at the club center with
layer offset 9, then fade and destroy themselves. These represent net balance
increases (including refunds), not individual guest transactions.

## Phase 3: crowd and security

`GuestController.luau` owns the client crowd, using `GuestNavigation.luau` for
2D grid routes around furniture. Six guests initially queue outside `(1,1)`;
admissions and arrivals build toward a maximum of 36. A blocked entrance holds
the queue until reopened. Guests reserve dance-pad positions; High Rollers prefer
reachable spots alongside `VelvetVIPBooth` furniture. If no feature is available,
guests chat on reachable floor tiles and retry. Visits end and new guests arrive.
Moving or selling furniture invalidates routes and reservations. Successful
Drop Bass requests rally eligible guests to actual dance pads.

Every ninth arrival is a red-shirted Rowdy Crasher. Uncovered Crashers reduce
nearby guests' happiness; it recovers away from them, and unhappy guests leave.
A `BouncerStation` draws a red isometric coverage ring using its configured
`EffectRadius`. Its UI bouncer intercepts a reachable covered Crasher, escorts
them through the entrance, and returns to the post. Each bouncer escorts one
guest at a time; covered Crashers stop lowering happiness while awaiting escort.
Removing a station cancels its interception and removes its staff and ring.
Fully blocked routes wait for a layout change rather than passing through walls.

Crowd timings and limits are in `GameConfig.CROWD`. These are client visual
behaviors: happiness does not currently change server income, stock, popularity,
or luxury. The server retains control of the economy; no guest movement remotes
or Roblox characters are created.

## Phase 4: music, celebrity missions, and expansion

Use **DJ Genres** to select Electro, HipHop, or SynthPop. `MusicController.luau`
plays the configured genre playlist through SoundService, advances when a track
ends, and stops when the DJ set expires. Empty playlists stay silent. Failed
tracks time out and are skipped; an entirely unavailable playlist stops retrying.
Add only original/permitted audio IDs to `GameConfig.MUSIC_GENRES` (`Playlist`,
or the single-track `SoundId` fallback). All asset references stay in GameConfig.

Celebrity visits begin after 30 seconds, last 120 seconds, and recur every 240
seconds. Builderbeat VIP, DJ Blox, and Pixel Popstar are original parody visitors
with named VIP sprites. A reserved crowd slot permits a celebrity to join a full
regular crowd. Their mission requires a VIP booth, their preferred genre, stocked
mocktails, and an active DJ set for 30 accumulated seconds. Progress and the
one-time reward are server-controlled and persisted. The mission banner shows
requirements, time remaining, and completion. The server evaluates facilities;
it does not trust client sprite positions or happiness for payouts.

**Expand** buys the next square layout tier: 12, 14, 16, 18, then 20 tiles per
side, costing $3,000 / $6,000 / $10,000 / $16,000 / $24,000. Existing furniture
stays in place. Prices and limits are authoritative on the server.

## Phase 5: saves and friend clubs

`DataManager.luau` stores versioned profiles with UpdateAsync session leases,
45-second autosaves, leaving-player saves, and BindToClose shutdown saves. Leases
last 180 seconds and are renewed on successful saves. Competing sessions cannot
acquire an unexpired lease; stale owners cannot overwrite a new owner. Failed
loads and unknown schemas never fall back to a replacement starter save. Saving
briefly pauses economic mutations; unrecoverable save failures stop the session.
Only whitelisted serializable ClubState fields are saved, and totals are derived
again from furniture on load. DJ/cooldown timestamps keep their wall-clock meaning;
there is no offline income or offline mission progress.

**Studio preview is session-only by default**, with a persistent HUD notice.
Live servers always use DataStoreService. For persistence testing, publish a
separate test experience, enable Studio API access there, and set
`GameConfig.PERSISTENCE.StudioSessionOnly = false`. Avoid testing against a live
production store. Roblox describes the API-access requirements and UpdateAsync
behavior in its [Data stores documentation](https://create.roblox.com/docs/cloud-services/data-stores).
The lease design follows the responsibilities described in Roblox's
[player data guidance](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing).

The bottom **Friends Bar** pages through Roblox friends, with online status when
available. Select a friend to inspect their latest saved layout, or their current
layout if they are in this server. Visiting displays a read-only snapshot: your
own club keeps running, and **Return Home** restores its current state. Refreshing
a visit fetches another snapshot. Friends without a saved club show an explanatory
message. Friend API failures are surfaced for retry. Server checks enforce actual
friendship and prevent building, restocking, changing genres, or expanding while
visiting; private cash/cooldowns are omitted from the visitor snapshot.

**Tip DJ $50** requires a friend's club with a DJ booth, sufficient funds, and a
60-second sender cooldown. The sender's debit and outgoing transfer are saved
together before delivery. A monotonic sender sequence makes recipient credit
idempotent across retries, including an interrupted response. Outgoing transfers
retry during autosave/rejoin; incoming credits merge into the recipient's next
save/join without overwriting an active session. A crash before delivery can leave
a tip pending until the sender rejoins. Preview tips require both players in the
same Studio server. Tips are in-game Cash only.

## Phase 6: procedural visual remake

ClubArt.luau draws a 2:1 floor, streets, walls, city facades, detailed furniture,
and shop illustrations from UI shapes. Empty assets have procedural fallbacks;
configured furniture images remain supported. Dance lighting updates at 10 Hz.
Guests have larger heads, varied skin tones, six hair/headphone/cap styles, and
animated limbs. Ordinary labels appear only when happiness needs attention.
Room geometry is cached across economic updates and furniture edits.
The hover cursor matches the 128x64 tile diamond.

This is an original procedural interpretation of the references. Painted sprite
art remains a future art pass. Room framing, gradient-mask rendering, depth
ordering, small-screen controls and maximum-club FPS need Studio review.
Polygons use gradient-masked right triangles with constant instance counts.
